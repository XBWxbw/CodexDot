# VRS 可变速率着色：原理、收益与限制

- 原讨论日期：2026-10-23
- 归档日期：2026-10-28

> 本文整理自历史技术讨论，保留原有技术边界及公开参考链接；归档时未重新核验最新引擎、API 或设备支持状态，也不是新增的实机性能测试。具体支持与收益需按实际版本、平台和驱动验证。

VRS（Variable Rate Shading）的核心，是把“像素覆盖精度”和“像素着色频率”拆开。

屏幕仍然可以输出 1920×1080，但并不要求这 200 多万个像素都各自执行一次完整的 Fragment／Pixel Shader。部分区域可以让多个像素共用一次着色结果。

## 1. 普通着色与 VRS 有什么区别？

先不考虑 MSAA、遮挡和边缘情况：

- 1×1：一个像素执行一次着色。
- 2×1：横向两个像素共用一次着色。
- 2×2：四个像素共用一次着色。
- 4×4：十六个像素共用一次着色，具体硬件不一定支持。

假设一块平坦墙面占据 100×100 像素：
- 1×1 理想情况下需要 10,000 次着色。
- 2×2 理想情况下只需要 2,500 次。

少掉的是 Shader 调用，不是把输出纹理从 100×100 改成 50×50。

## 2. GPU 具体怎么做？

可以把硬件光栅 VRS 简化为四步：

第一步：正常确定三角形覆盖哪些像素、哪些采样点。

第二步：根据着色速率，把同一图元的覆盖区域组织成较大的“粗片元”，例如覆盖 2×2 像素。

第三步：为粗片元生成 Shader 输入，只执行一次材质读取、纹理采样、数学运算和相关光照计算。

第四步：把这次输出用于该图元实际覆盖、且通过相应测试的采样点。

因此，VRS 不是“先把四个像素全部算好，再挑一个复制”，而是一开始就少算三次。

也不是把不同三角形的颜色无条件糊在一起。覆盖、深度和模板测试仍保留原有采样精度，所以几何轮廓可以保持精细，而表面内部的材质细节变粗。[Microsoft VRS 规格](https://microsoft.github.io/DirectX-Specs/d3d/VariableRateShading.html)

但要注意：用 Shader 的 discard／alpha test 做出来的树叶、栅栏轮廓，不是纯粹的几何轮廓，不能据此保证不受影响。

## 3. “可变”体现在哪里？

不必让整个屏幕都用 2×2，可以按重要性分配：

- 主角脸部、文字、细小高光：1×1。
- 远处墙面、低细节区域：2×2。
- 运动模糊明显或视觉关注度低的区域：使用硬件支持的更粗速率。

常见的控制来源有：
- 按 draw call 指定。
- 按图元指定。
- 提供一张屏幕空间的着色速率图，告诉 GPU 各区域采用什么速率。

这些来源可以按 API 的合并规则组合。注意，“速率图一个格子管理多大屏幕区域”和“一次着色覆盖 2×2 像素”是两个不同尺度，不能混为一谈。

注视点渲染就是一种典型策略：视线中心保持精细，外围减少着色。VRS 是实现这种策略的一种手段，并不等于注视点渲染本身。

## 4. 它到底省 ALU，还是省带宽？

最直接省的是片元 Shader 的执行工作：
- 算术运算。
- 纹理采样指令。
- 对应的寄存器读取、结果传递等活动。

如果一次着色本来要做很多次采样和复杂 BRDF 计算，少调用几次 Shader，收益就可能很大。

但它不会自动同比减少：
- 顶点与几何处理。
- 光栅化、覆盖和深度／模板处理。
- 混合操作。
- 全分辨率颜色或 GBuffer 附件的存储量。

纹理采样次数减少，也不代表 LPDDR 读取字节数同比减少，因为原来的采样可能已经命中缓存，还会受到 mip 选择等因素影响。

所以，2×2 VRS 的意思不是“带宽变成四分之一”。Arm 的示例甚至出现 GPU cycles 降低、读取带宽却略有增加的情况。[Arm 的 VRS 分析](https://developer.arm.com/community/arm-community-blogs/b/mobile-graphics-and-gaming-blog/posts/variable-rate-shading)

从功耗角度看：VRS 更像是直接减少重复的像素着色工作，而不是直接压缩所有内存流量。

## 5. 为什么画质会受影响？

因为原本四个像素可以有不同的 UV、法线、粗糙度和光照结果，现在共享一次着色，空间变化被简化了。

容易暴露问题的地方包括：
- 细线、文字和高频纹理。
- 锐利高光、细密法线贴图。
- Shader 计算出来的边界。
- 着色速率变化时的块状感或闪烁。

还有一个底层细节：纹理采样的隐式 mip 选择通常依赖 UV 导数。粗着色时，相邻 Shader 调用之间跨越更大的屏幕距离，导数会发生变化，采样往往倾向于更粗的 mip。因此 VRS 的效果不只是“复制颜色”，纹理过滤行为也会改变。[Vulkan Shader 规格](https://docs.vulkan.org/spec/latest/chapters/shaders.html)

## 6. 2×2 VRS 与普通的 2×2 quad 不是同一回事

普通 GPU 为了计算导数，通常把四个像素着色调用组织成一个 2×2 quad。它通常仍是四次着色调用，不是一次。

启用 2×2 VRS 后，每次调用覆盖范围变大；四个粗着色调用组成的 quad，可以覆盖 4×4 屏幕像素。

因此，“GPU 本来就是按 2×2 执行”不代表它本来就在做 VRS。小三角形、边缘和辅助调用，也会让真实收益低于理想的四分之一调用量。

## 7. 放到 Forward／Deferred 里怎么理解？

这是从管线结构推导的区别，具体还要看 UE 在哪些 pass 接入 VRS：

Forward：
材质与光照经常在同一个片元 Shader 里。降低着色频率，可以同时减少这部分材质和光照计算。

Deferred：
如果只对 Base Pass 使用 VRS，减少的是材质和 GBuffer 生成计算；GBuffer 分辨率不会自动变小，后面的 Lighting Pass 也不会自动少算。

光照阶段若也是像素着色器绘制，可以另行应用 VRS，但需要保护深度、法线等不连续区域。如果光照通过 Compute Shader 实现，硬件光栅 VRS 不会自动减少它的计算，需要另一套算法。

## 8. 为什么 2×2 不等于整帧快四倍？

举一个仅用于理解的理想例子：
- 原帧时间的 40% 是能被 VRS 缩减的着色工作。
- 另外 60% 不受影响。
- 假设这 40% 真能降到四分之一。

新帧时间就是原来的 60%＋10%＝70%，即缩短 30%，而不是缩短 75%。实际还会有边缘、调度及速率图等开销。

功耗也一样：锁帧后，省下的工作可能变成更低频率或更长空闲时间；不锁帧时，则可能主要变成更高 FPS。

最后可以这样记：降低分辨率是“少画一些像素再放大”；VRS 是“保留精细的像素覆盖，但让部分像素少算几次着色”。它主要针对像素着色成本，尤其适合计算昂贵、又允许局部降低着色细节的区域。
