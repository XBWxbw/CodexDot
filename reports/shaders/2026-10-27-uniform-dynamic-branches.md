# Shader 动态分支：运行时固定路径为何仍可能影响性能

- 原讨论日期：2026-10-27
- 归档日期：2026-10-28

> 本文整理自历史技术讨论，保留原有技术边界及公开参考链接；归档时未重新核验最新引擎、API 或设备支持状态，也不是新增的实机性能测试。具体支持与收益需按实际版本、平台和驱动验证。

运行时固定走一个分支仍可能有性能开销，但要准确区分：没有分支发散，不等于没有额外开销；有动态分支，也不等于一定很慢。

如果开关由 CPU／材质参数传入，同一次 draw 的所有像素都走 A，这通常是动态分支中比较理想的情况。

## 1. 首先，“固定”有两种完全不同的含义

- 整个 draw 都走 A：没有组内分支发散。
- 每个像素一直固定，但有些像素走 A、有些走 B：仍可能发散。比如屏幕左边一直 A、右边一直 B，跨越边界的执行组仍可能需要处理两条路径。

GPU 在这里关心的是同时执行的一组线程是否一致，不是这个条件过去几百帧有没有改变。不同 warp／wave 各自选择不同路径，本身不构成组内发散。

## 2. 如果确实全部走 A，B 的计算还会执行吗？

如果最终机器码是真正的分支，而且相关工作没有被移到分支外，B 的算术与采样可以跳过。不是必须“把 A、B 都算完”。

但源码的 if 不保证最终一定是跳转：
- 短分支可能被转换成条件选择／谓词执行。
- 一些计算可能被提前到分支外。
- HLSL 的 branch 与 flatten 就代表不同的编译方向：后者计算两边再选择。

所以“运行时条件永远为 false”不能单凭源码证明另一侧完全没执行。[Microsoft HLSL 分支说明](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-if)

同理，不要为了“避免 if”把两条昂贵路径改成 lerp／mix。这样可能反而把本可跳过的工作都算了；对于两三条简单数学运算，选择指令才可能更合适。[Arm 最佳实践，第 102–103 页](https://documentation-service.arm.com/static/67a62b17091bfc3e0a947695)

## 3. 即使 B 真没执行，也可能拖慢 A：寄存器是关键

很多 GPU／编译路径会为整个编译好的 Shader 确定寄存器需求，而不是每次看到参数选 A，就重新按“只有 A”分配。

举个假设：
- 单独编译 A，所需工作寄存器很少。
- B 有复杂计算和大量同时存活的临时值。
- 将 A、B 合成一个动态 Shader 后，整体寄存器需求可能升高。
- 即使实际总走 A，也可能因此降低并发驻留能力、削弱延迟隐藏。

注意：
- 不是 A 寄存器数＋B 寄存器数简单相加，互斥路径可以复用。
- B 很长也不必然寄存器多，关键在变量活跃区间和编译结果。
- 寄存器增加也不必然降低 occupancy，要看是否跨过资源阈值。
- B 自己的 spill 指令若只在未执行路径内，不等于这些访存仍会执行。

AMD 官方明确举过“从未执行的分支也可能抬高整个 Shader 寄存器需求”的情况，同时强调 occupancy 下降不必然等于性能下降。[AMD Occupancy Explained](https://gpuopen.com/learn/occupancy-explained/)

这就是“明明另一个分支完全没跑，为什么纯 A 版本还是更快”的一个重要原因。

## 4. 另外还有编译优化与管线状态的影响

即使没有发散，仍可能有条件读取、比较和控制流开销；分支也可能限制指令调度，例如纹理读取能否提前发出。通常不应只盯着那一条跳转指令。[NVIDIA Shader 指南](https://developer.nvidia.com/blog/advanced-api-performance-shaders/)

结合隐藏表面消除（HSR），还要特别注意：
如果 B 含 discard、写深度或资源副作用，运行时不走 B，不一定就让整个 Shader 获得“纯 opaque A”的全部硬件优化资格。编译器／驱动可能仍需保守处理，具体取决于平台，不能一概说全部 Early-Z 都会失效。

编译时真正删掉 B，则更有机会同时消除代码、资源需求及相关限制。

## 5. 工程上怎么选？

适合用 uniform 动态分支：
- 需要运行时切换。
- 同一执行组条件一致。
- 能跳过一大段真正昂贵的工作。
- 两条路径的资源需求差距不大。
- 希望控制 Shader 变体数量。

更值得做静态变体／专门化：
- 该选项在一个材质／设备配置中长期固定。
- A 很轻、B 很重，怀疑寄存器影响。
- B 引入 discard、深度输出等特殊行为。
- 这是高像素覆盖率、性能敏感的 Shader。

在 UE 中，普通标量参数即便永远设成 0，也不能当作编译期常量。Static Switch 可以排除不选中的材质分支，但会带来变体数量、编译和管理成本。[Epic Static Switch 说明](https://dev.epicgames.com/documentation/unreal-engine/material-function-expressions-in-unreal-engine)

最直接的验证：做两个画面完全相同的版本，一份只保留 A，另一份保留 A/B 动态分支但始终选择 A。比较实际 GPU 时间、寄存器数、spill、occupancy，以及采样和指令的实际执行情况，不要只比较源码指令数。

一句话：如果生成了真正的 uniform 分支、寄存器和管线资格都没变，开销往往很小；真正可能出大问题的，是未执行分支仍影响了整个 Shader 的编译与资源配置。
