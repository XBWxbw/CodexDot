# 移动端功耗：带宽与 ALU 的优化收益

原讨论日期：2026-10-22  
归档日期：2026-10-28

> 本文是历史技术讨论的整理归档，保留当时的结论、适用边界与公开参考链接；不是新增设备基准测试，也不是对当前平台支持状态的重新审计。涉及实验数据时，仅作为匿名报告的局部案例，不代表所有设备。

先说结论：在受控测试中，“这个场景里，减少 ALU 工作比减少带宽更省电”完全可能成立。“移动端功耗大头在带宽”不是一个普遍成立的定律，更准确的说法是：外部内存访问代价高，是移动端必须重点控制的耗能来源，但不保证占比最大。

## 1. 单次操作贵，不代表总功耗最大

“从外部内存取数据，比做一次简单运算贵”比较的是单次能耗；游戏实际功耗还取决于每秒发生多少次。

一份数据进入缓存、寄存器后，可能参与很多次计算。因此，即使单次 ALU 运算便宜，庞大的运算量，加上寄存器读写、指令调度和数据传递，也可能比外部访存消耗更多能量。

所以，“数据搬运昂贵”和“某个 Shader 的计算更耗电”可以同时成立。Arm 的官方说明也把 GPU 活跃周期、外部内存事务和 CPU 驱动工作分别列为耗能来源，而不是给带宽一个固定的第一名：[Arm GPU 能效说明](https://developer.arm.com/community/arm-community-blogs/b/mobile-graphics-and-gaming-blog/posts/energy-efficiency-in-gpu-applications-part-1)。

## 2. 100 mW／(GB/s) 是局部实验斜率，不是通用常数

原讨论包含一个匿名报告的局部实验关系：“带宽增加 1 GB/s，功耗增加约 100 mW”。此处仅用于解释量纲与归因，不构成独立核验的设备基准。

这个斜率相当于约 100 pJ/字节，或 12.5 pJ/bit。但它只是这组实验中的边际成本，不是手机通用的“每字节耗电常数”。

它不能直接说明整个内存子系统只消耗 100 mW，因为还可能有基础功耗、刷新、控制器和互连等成本；频率、电压、访问模式变化后，斜率也可能变化。若只是“某场景带宽为 1 GB/s、测得功耗为 100 mW”，没有做差分，就更不能直接算出上述斜率。

假设同一工作区间内这个斜率近似成立：减少 2 GB/s，大约节省 200 mW。如果减少 Shader 计算实际能省 500 mW，在这些条件下，应优先优化后者，而不是为了遵守“带宽最贵”去选前者。

## 3. ALU 优化可能同时省了工作量、活跃时间和电压

减少 Shader 运算，收益可能不只是少执行几条指令：
- GPU 更早完成一帧，在锁帧条件下有更多空闲时间。
- 系统可能用更低频率满足同一个帧率目标。
- 如果随降频进入更低电压档，动态功耗还会进一步下降。

动态功耗可以粗略理解为随“开关活动 × 电压平方 × 频率”变化。因此一次 ALU 优化如果触发降压，整块 GPU 的功耗变化可能很明显。

反过来，减少带宽但没有改变 GPU 活跃时间或频率档，可能主要只省下访存相关的增量。这个对比不能说明 ALU 每条指令都比访存贵，只能说明前者在当前场景带来的系统级收益更大。

## 4. “带宽瓶颈”和“功耗大头”也不是一回事

瓶颈回答的是“谁限制了完成速度”；功耗占比回答的是“能量消耗在哪里”。

即使帧时间被内存等待限制，也不能据此断定 DRAM 是耗电最多的部件。反过来，外部带宽不高，也不代表 GPU 内部的缓存、寄存器和纹理单元没有大量数据活动。

所以不要用“带宽是不是瓶颈”，直接推导“优化带宽是不是最省电”。

## 5. 必须核对“总带宽”的统计位置

它是 GPU 对外读写、内存控制器统计的 LPDDR 读写，还是工具根据资源访问估算的流量？这几个数不一定相同。

例如 Arm 的 G715 计数器文档明确说明：GPU 计数器只能看到 GPU 边界，不能直接看到下游系统缓存或片外 DRAM 带宽。因此 GPU 的 external read/write 也未必等于实际 LPDDR 流量。这个边界需要按具体芯片和工具确认：[Arm 计数器说明](https://github.com/ARM-software/libGPUCounters/blob/main/docs/immortalis-g715_and_mali-g715_counter_reference.html)。

## 6. 对游戏优化，最终应怎么判断？

建议分两轮测：
- 归因测试：尽量固定 GPU／内存频率、温度和工作量，分别改计算与访存，观察各自增量。不能锁频时，至少记录频率变化，避免把 DVFS 收益误认成单条指令成本。
- 实际收益测试：恢复正常 DVFS，锁定相同 FPS、分辨率和画质目标，看稳定后的平均功耗与每帧能耗。

同时记录 GPU 毫秒、频率、活跃度、每帧外部读写字节数。别只看 GB/s：不锁帧时，优化后 FPS 上升，单位时间带宽反而可能增加，尽管每帧已经更省。

这样的结果至多支持“当前场景的计算优化收益更大”，不能推出所有移动端游戏都应优先优化 ALU。

归因还需要记录 SoC／GPU、测量工具、功耗统计范围（整机、SoC 或 GPU 电源域），以及锁帧、锁频条件，才能区分计算本身的成本与频率、活跃时间共同变化的收益。
